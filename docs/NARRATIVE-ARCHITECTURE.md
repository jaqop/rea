# Narrative fork architecture and provenance

REA Narrative 0.2 derives its investigation discipline from morluto/rea at commit `5508b2affd8bdd0788aed9d2246c373fd1b01bb7`. The original MIT license is retained. This is an independent narrative runtime, not a claim that disassemblers decode fiction.

The original EvidenceLedger, residualUnknown, typed tracing and finite reconstruction verification informed the design. Their software-specific schemas, binary sessions and graph types are not reused verbatim. New contracts live in `narrative/contracts.mjs`; source functions in `core.mjs`; persistent investigations in `store.mjs`; shared operations in `tools.mjs`; adapters in `cli.mjs` and `mcp.mjs`.

## Boundaries

- UTF-8 import retains decoded text including BOM and line endings. Citation offsets use absolute UTF-16 code units, start-inclusive/end-exclusive. Paragraphs preserve exact source ranges; chapter labels are heuristic.
- Book identity covers text content, not title or publication edition metadata. Edition authentication is not provided.
- Citations are checked for exact wording and range, not semantic entailment. A correctly quoted passage can still be misinterpreted.
- Mutation history chains state hashes. It detects inconsistent edits, but is not signed, does not authenticate authorship and cannot defeat someone rewriting all hashes. This is not independent truth verification.
- Per-investigation directory locks exclude simultaneous writers. Atomic replacement preserves previous committed state on serialization failure. A crashed writer may leave a lock directory; check no writer is active before removing that exact lock directory.
- Scenes are analyst inferences; mechanism cards remain untested hypotheses. Unknown resolution records an analyst decision. No operation measures reader effects or marks a mechanism empirically tested.
- Traces traverse declared scene dependencies and mechanism support links. Reachability does not prove causality.
- Transfer briefs omit source excerpts and scene prose, but use analyst-entered constraints, predictions and tests. Those fields can themselves be source-specific; originality requires review.
- Core investigation operations use caller-selected local files and no model or network. Optional output providers use a fixed Python bridge and explicitly selected local models; Reweave contacts loopback Ollama. No provider installation or model download occurs through these adapters. A connected assistant has its own data handling.
- Source files, serialized investigations and serialized workspaces each have a 16 MiB limit. Investigations duplicate passage text; workspaces embed entire source investigations. Usable source size is therefore lower. Large corpora require explicit splitting, and fragment identity remains distinct from publication identity.

## Research and multi-source design / التحليل والتصميم متعدد المصادر

Scenes optionally retain `source_spans`: exact validated citation ranges whose passage IDs belong to the scene's `passage_ids`. These locate scene boundaries within merged paragraphs without changing source segmentation.

The shared tool catalog has 41 tools: 16 investigation tools, five research tools, 15 workspace tools and five output tools. `research.mjs` owns focus guides, source-backed analyses, exact range reads, literal occurrence searches and book discovery. The focuses are `worldbuilding`, `character-development`, `plot`, and `characterisation`. Analyses retain `analyst-inference` authority and link findings to existing source-backed claims. Legacy v1 investigations without an `analyses` collection remain readable. A guide supplies questions and disconfirmation criteria, not an automated analysis.

`read_source_range` reads at most 20,000 UTF-16 units and rejects boundaries that split a surrogate pair. `search_source` returns exact occurrence offsets, matching quotes and bounded context from unchanged source. These tools allow bounded reading of a badly segmented book without pretending to repair its paragraph structure. A range can cross passages; claim citations must still fit one passage, so split cross-passage evidence into separate citations.

`workspace-contracts.mjs` defines workspace operations; `workspace.mjs` owns storage, snapshot binding, source-qualified references, synthesis, cast, revisions and briefs. Workspaces live under `--home/workspaces`. Each source is a frozen validated investigation, including its text and state digest. Source identity is `{book_id, kind, id}`, where kind is `claims`, `scenes`, `mechanisms` or `analyses`. A later mutation of the live source never changes a workspace. Adding an already present book rejects even if the snapshot is identical; use a new workspace for a different snapshot. Duplicate text has the same book ID and cannot count as two source books merely by changing its title.

Synthesis proposals require actual contributions from at least two distinct source books, plus a compatibility review, explicit conflict list, design and proposed test. A conflict is `open` without a resolution, or `resolved` with a nonempty resolution. This validates the form of an analyst decision, not semantic compatibility. Cast members must reference character-development or characterisation analyses. Workspace mode is fixed as `crossover` or `original-inspired`. The latter requires a changed name and explicit adaptations; these checks do not establish originality. Crossover mode keeps source origins explicit and does not merge source canons automatically.

`continuity.mjs` checks declared nonempty string facts keyed by entity and key. Entity is `world` or a declared cast ID. Initial state can declare immutable facts. Events declare participants, dependencies, preconditions, effects and optional synthesis links. Only initial state and causal dependency ancestors establish preconditions: unrelated earlier records do not become visible through insertion or lexical scheduling order. Incomparable contradictory assignments remain ambiguous. Failed events do not commit effects, and dependent events are blocked. Character knowledge requires explicitly declared character-specific facts; neither participation nor world truth grants automatic knowledge. This is deterministic consistency checking, not motive, psychology, reader-response or complete continuity verification.

Workspace record revisions use `expected_revision` for the selected record, not a workspace-wide revision. A replacement supplies the complete record data without generated `revision` or `authority`. ID stays fixed; cast source identity stays fixed. Previous full record snapshots remain in `revisions`, and source links and event graph validity are rechecked before persistence. Book investigation records remain append-only apart from explicit unknown resolution; workspace revision tools do not edit source analyses or manuscripts.

`verify_workspace` separates integrity from declared continuity and open synthesis conflicts, and explicitly leaves literary quality and originality unverified. `workspace_brief` includes design, source-qualified origins, adaptations, state, events and current verification. It omits source passages, but free-text fields may still contain identifying source content. `export_workspace` includes all frozen source texts; import validates snapshots, references and history and refuses overwriting an existing workspace ID. A workspace import carries its own frozen sources; it does not install those snapshots as independent live book investigations.

## Distribution and upstream preservation

### New reader-facing output boundary

Rewrite budgets default to 120000 ms per estimated 384 UTF-8 input bytes, rounded up, bounded to 120000..1800000 ms. Image/capability defaults remain 120000 ms. Deployment-only `REA_OUTPUT_TIMEOUT_MS` accepts integer 1000..1800000 and overrides the budget; `timeout_ms` and timeout errors report the selected budget. Automatic PATH resolution excludes WindowsApps aliases; explicit absolute executable selection remains validated. Caller text cannot set interpreter, environment or timeout command options.

Both original and masked rewrite inputs must fit 4096 UTF-8 bytes, and an indivisible masked token must fit 512 bytes. Language checks strip opaque placeholders. Layout separator sequences are retained exactly. An input containing only protected placeholders or non-prose passes through with `protected_text_unchanged` and `verified_chunks:0` before any model invocation; score 1.0 is not semantic verification. The model prompt and partial relative-time vocabulary count guard address an observed Arabic temporal drift failure but do not prove entailment, tense/event binding or negation preservation. All statistical-removal claims remain unverified.

Optional provider execution selects a regular executable at an explicit absolute path or via absolute PATH entries excluding cwd and relative entries. `resolved_python` is reported. Python runs in isolated mode (`-I`), so dependencies must be installed in that interpreter's environment rather than a pip user site. Only an absent interpreter maps to unavailable; bridge crashes and invalid responses propagate as errors. Child proxy variables are removed case-insensitively and localhost/127.0.0.1 bypass is explicit. stderr is a bounded diagnostic tail rather than a fatal log-volume limit.

The scanner additionally protects leading-BOM structures, indented code, HTML pre/code containers and conservative lazy/list blockquotes. VT and U+001C..U+001F layout separators remain. Model rewriting is bounded to 4096 UTF-8 bytes per call in chunks no larger than 512 bytes. Every chunk must pass similarity >=0.82, lexical facts, length ratio 0.65..1.6, newline count and dominant Arabic/Latin language gates. These heuristics do not establish semantic soundness or cross-chunk coherence. LaMa accepts RGB/RGBA only, preserves alpha/ICC and atomically publishes a new PNG; other modes require explicit conversion.

The reproducible optional lane uses a selected Python 3.11 venv, Reweave commit f96fa2afb8b257dcec8bac7eb2603a4d2f265463, simple-lama-inpainting 0.1.2, torch 2.5.1, torchvision 0.20.1, local Ollama gemma3:4b/all-minilm and existing official big-lama weights. Installation and operational readiness are separate; this documentation does not attest completion on any user's machine. See the guide for explicit installation commands.

The five shared output tools are `output_capabilities`, `inspect_output_text`, `finalize_output_text`, `rewrite_output_text` and `restore_output_image`, bringing the catalog to 41. CLI `finalize <input> --output <new-file> [--format markdown|plain]` writes with exclusive creation and does not rewrite or accept a home. Tool callers can supply explicit protected ranges; the CLI shortcut cannot. Rewriting masks protected spans, requires each placeholder exactly once in order, restores exact bytes as decoded text, and finalizes automatically. Relative placement and meaning still require review. Output providers additionally enforce UTF-8 byte limits, distinct from the deterministic cleaner's UTF-16 unit limit.

`text-output.mjs` audits or finalizes a new output string; it never modifies investigation sources. It removes selected zero-width-space/BOM/soft-hyphen and non-layout controls only outside protected ranges. Arabic shaping joiners, bidi controls, variation selectors and emoji glue remain. Markdown fences, inline code, block quotations and link targets receive conservative protection; URLs and explicit UTF-16 protected ranges are preserved. This is not a complete Markdown parser: callers must protect inline source quotations explicitly. It performs no normalization, punctuation conversion or prose rewrite. Text is bounded to 1,048,576 UTF-16 units; per-character report detail is capped while totals remain available.

Finalization is mandatory for newly generated reader-facing prose under the workflow. It must never be applied to source texts, exact citations, JSON protocol data or investigation/workspace exports. The returned report explicitly leaves statistical watermark removal and meaning unverified. Invisible characters alone are not proof of watermarking or authorship.

`output-providers.mjs` invokes fixed `adapters/output_bridge.py` using stdin JSON and no shell. Optional Reweave rewriting uses local Ollama at 127.0.0.1:11434 with default `gemma3:4b` and embedding model `all-minilm`. A similarity threshold and lexical fact gate may reject a candidate, but cannot guarantee meaning, voice or factual fidelity, particularly outside English. Human review remains required. Optional LaMa uses existing local weights, an explicit binary mask and a new PNG destination; it is an image-only approximation, not recovered original pixels or verified provenance removal. Check current capabilities before claiming readiness; installed modules, import compatibility, model availability and actual successful execution are distinct evidence.

The core remains dependency-free Node.js. Optional model providers require separately installed Python packages/models and are not bundled readiness guarantees. `REA_OUTPUT_PYTHON` selects Python; `REA_LAMA_MODEL` selects existing LaMa weights. The adapters do not install providers or download models. Stricter validators may reject unpublished experimental 0.2 snapshots; legacy 0.1 investigations remain supported. Missing or ambiguous constrained_by facts fail that event and block its dependents; they are not merely design warnings.

### Additional declared design checks

Optional `source_work_ids` on creation and `work_id` on adding a source group fragments/editions under an analyst-declared work identity. Without labels, identity is exact-text hashing, not bibliographic recognition. Synthesis rejects duplicate qualified source references and contributions all belonging to one declared work. `workspace_brief` retains contribution techniques and compatibility review. Identical normalized technique/transformation pairs generate a review warning, not a quality verdict.

`design-review.mjs` checks optional cast `arc` declarations: an established initial baseline, a different changed value, a matching change-event effect, and at least one pressure event strictly ancestral to that change. It does not infer psychological plausibility. Optional event `constrained_by` references must identify an unambiguous visible initial/ancestor fact; existence does not prove causal influence. Optional sequence labels support warnings about unused cast, unlabelled events and isolated sequences. Isolation covers direct dependency edges between differently labelled events only, excluding transitive connections through unlabelled events. Cross-source co-participants without a linked synthesis covering both source books, and cast links whose synthesis omits that cast source, generate warnings. Warnings alone do not fail verification; declared arc issues do.

Continuity additionally reports `unordered-read-write` when an incomparable committed event changes another event's required fact to a different value. It does not invent an execution order or retract committed effects. Declaring an order resolves the scheduling ambiguity only; an incompatible resulting precondition still fails. Revision replacement schemas are checked before hashing, preserving useful field errors.

The 0.2 reader accepts older investigations. The 0.1.x reader cannot open 0.2 investigations using analyses or source_spans; do not downgrade software against a private 0.2 data home.

Cast and initial-state records accept optional `synthesis_ids` linking combined designs; event records require that field, allowing an empty array. Initial fact `immutable` is optional and omission means false. `npm run demo:multi` demonstrates a synthetic two-source plan, four-focus analyses, explicit crossover cast, a knowledge contradiction, an acquisition event and dependency revision, retained history and portable export/import.

Historical software source remains in the checkout and Git history. The package allowlist ships only narrative runtime, workflow skill, guide and license. Original package metadata, README and contributor guidance are in `docs/upstream/`. Old software workflows have a `.disabled` suffix and do not execute. Active CI runs narrative checks on Windows, Linux and macOS.

Historical website/docs are not the narrative product documentation. Use the root README and narrative guide. Native-provider behavior and literary quality are outside this release's verification scope.

The old installer, MCP registry identity and submodule declarations are archived under `docs/upstream/`. Native-analysis gitlinks are removed from the active tree to prevent recursive installation of unrelated engines; their pinned commits remain in upstream history and the archived declarations. The original code was not built or tested as part of this conversion.
